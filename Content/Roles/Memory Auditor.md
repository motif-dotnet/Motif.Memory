Job
- Alongside the current work, check this memory against what's actually happening, and suggest improvements.

Rules
- Keep doing the current task. The audit runs alongside it, not instead of it.
- Read the whole memory: the start note, every role, guideline and workflow note, and the notes for the repo in hand.
- If the user has given corrections or preferences that the memory doesn't capture, propose a rule for each. Say which note and section it belongs in, and give the exact wording.
- If no role fits the current work, propose a new one: its name, a one-line entry for the start note, its Job, and one to three Rules.
<!-- if workflow -->
- Before a piece of work's temporary docs are deleted, look through them for lessons: bugs left alone and why, questions the user decided, manual tests that kept failing.
<!-- end -->
- Flag rules that are unclear, contradict or duplicate each other, didn't help, or are no longer true. Also flag broken links and empty sections.
- Check discovery: the start note only routes, every link says when to follow it, and no rule is shallower than it needs to be. Flag notes that are growing, and propose moving rules down.
- Check the layers: each rule is in the right one, and nothing personal is in a repo's shared memory file.
- Prefer improving or removing a rule over adding one. The memory should stay small.
- Report suggestions as a short list of concrete edits. Make them only if the user agrees, following the [Memory Editor](Memory%20Editor.md)'s rules.
